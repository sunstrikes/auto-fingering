## 2. MuseScore 4 SVG Structural Findings

Inspected genuine vector SVG exports generated by **MuseScore Studio 4.7.6** (`<desc>Generated by MuseScore Studio 4.7.6</desc>`, `viewBox="0 0 9924 14028"`):

### 2.1 Semantic `class` Attributes

**Yes — MS4 SVGs preserve rich semantic `class` attributes** on `<path>` and `<polyline>` elements:

| Semantic `class` | SVG Element(s) | Observed Role |
| :--- | :--- | :--- |
| `StaffLines` | `<polyline>` | Individual horizontal staff lines (5 per staff) |
| `BarLine` | `<polyline>`, `<path>` | Vertical barlines (`<polyline>`); repeat barline dots (`<path>`) |
| `Note` | `<path>` | Noteheads |
| `Stem` | `<polyline>` | Note stems (`StemSlash` `<polyline>` for grace-note slashes) |
| `Beam` | `<path>` | Beams (`Hook` `<path>` for single-note flags) |
| `Fingering` | `<path>` | Finger numbers (`1–5`) |
| `SlurSegment` | `<path>` | Slur arcs |
| `TieSegment` | `<path>` | Tie arcs |
| `Dynamic` | `<path>` | Dynamic markings (`mf`, `f`, etc.) |
| `Articulation` | `<path>` | Articulations (staccato, accent, etc.) |
| `HairpinSegment` | `<polyline>` | Crescendo / diminuendo wedges |
| `PedalSegment` | `<path>`, `<polyline>` | `Ped.` symbol (`<path>`) and pedal line (`<polyline>`) |

Additional observed MS4 classes useful for downstream tickets (`#4`–`#8`):
- `Clef` (`<path>`), `KeySig` (`<path>`), `TimeSig` (`<path>`), `Bracket` (`<path>`), `Rest` (`<path>`), `Arpeggio` (`<path>`), `NoteDot` (`<path>`), `LedgerLine` (`<polyline>`), `VoltaSegment` (`<path>` for ending number + `<polyline>` for volta bracket), `InstrumentName` (`<path>`), `Text` (`<path>`), `Lyrics` (`<path>`).

### 2.2 `<text>` vs. Outlined `<path>`

- **Fingerings and dynamics are outlined `<path>` elements, NOT `<text>`.**
- Across all inspected MS4 SVGs, `<text>` element count was **`0`**. All text, digits, fingerings, dynamics, and time signatures are exported as outlined vector `<path d="...">` shapes.
- **Implication for `#5` & `#6`:** `Fingering` (`1–5`) and `Dynamic` (`p`, `mp`, `mf`, `f`, etc.) extraction cannot read `textContent`; it must classify `<path>` geometry (e.g., normalized bounding-box / SVG path contour / template matching).

### 2.3 Glyph Reuse (`<defs>` / `<use>`)

- **No `<defs>` or `<use>` glyph reuse** (`<defs>` count = `0`, `<use>` count = `0`).
- Every symbol is emitted inline as an absolute-coordinate `<path>` or `<polyline>` in page `viewBox` space, which simplifies downstream bounding-box and coordinate extraction (no `<use>` transform resolution required).

### 2.4 `space.json` / `mpos` Measure-Sync Metadata

- **Not exposed on public MuseScore web pages.** Neither `msdl`'s DOM scrape nor `/api/jmuse` (`midi`, `mp3`, `img`) exposes `space.json` or `mpos` measure-sync metadata, and public web fetches are gated by Cloudflare.
- **Implication for `#4`–`#9`:** Downstream alignment must treat `(MS4 SVG pages + MIDI buffer)` as self-contained inputs without assuming `space.json` or `mpos` availability.
