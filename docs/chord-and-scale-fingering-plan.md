## 1. 问题背景与 12 调实测根因定位

当前指法求解器（[`src/solver/costModel.ts`](../src/solver/costModel.ts)、[`src/solver/handKinematics.ts`](../src/solver/handKinematics.ts)）完全基于纯物理几何距离、单指静态黑键惩罚与 2D 运动学手掌姿态求解，缺少**柱式和弦外框黑键豁免**、**和弦转位音程开口（Voicing Geometry）结构先验**以及**黑白键地形感知的 3+4 周期穿跨指建模**。在 12 个大/小调全量基准实测中暴露出以下 4 类系统性偏差：

### 1.1 柱式和弦被 `thumbBlackAvoid = 4.5` 与 `pinkyBlack = 1.152` 误伤
- **现象还原**（默认 `avoidThumbOnBlack: true`）：
  - **原位大三和弦**：`Db`（`Db-F-Ab`）、`Eb`（`Eb-G-Bb`）、`Ab`（`Ab-C-Eb`）右手被推导为 **`2-4-5`**（标准应为 **`1-3-5`**），左手被推导为 **`5-3-2`**（标准应为 **`5-3-1`**）。
  - **第一转位大三和弦**：`D`（`F#-A-D`）、`E`（`G#-B-E`）、`A`（`C#-E-A`）因最低音为黑键，右手被推导为 **`2-3-5`**（迫使 `3-5` 指硬撑纯四度，标准应为 **`1-2-5`**）。
  - **全黑键原位三和弦**：`F#` 大三和弦（`F#-A#-C#`）左手因 `pinkyBlack (1.152) > finger4 (0.35)` 被推导为 **`4-2-1`**（标准应为 **`5-3-1`**）。
- **代码根因**：
  - [`computeVerticalCost`](../src/solver/costModel.ts#L386-L534) 对所有黑键上的 `1` 指无条件叠加 `thumbBlackAvoid = 4.5`、对 `5` 指无条件叠加 `pinkyBlack = 1.152`。
  - 在钢琴演奏法中，“避免大拇指上黑键”仅针对**单音级进/音阶琶音穿指（Thumb-under）**（防止大拇指在黑键下方别扭穿指导致手腕外翻）；而在 **3 音及以上的柱式和弦**中，`1` 指与 `5` 指作为**和弦外框（Outer Frame）**同时落黑键是自然且固定的标准手型。

### 1.2 三和弦与四音和弦缺少“转位音程开口（Voicing Geometry）”结构先验
- **现象还原**：
  - 右手原位小三和弦 `Fm`（`F4-Ab4-C5`）因中音 `Ab4` 在黑键，2D 模型判定 `2` 指比 `3` 指略省力，输出 **`1-2-5`**（标准应为 **`1-3-5`**）；`Ebm` 原位（`Eb4-Gb4-Bb4`）输出 **`1-2-4`**（标准应为 **`1-3-5`**）。
  - 左手第二转位（四六和弦，下方四度 + 上方三度）在 `D/E/A/B` 大调及 `Cm/Fm/Gm` 小调上输出 **`5-3-1`** 或 **`5-3-2`**（标准应为 **`5-2-1`**，将下方四度大开口留给 `5-2` 指）。
- **代码根因**：
  - 2D 运动学模型对 `2` 指与 `3` 指在三和弦中间音上的舒适度区分极小（差值 `< 0.5`），容易被黑白键 Y 轴纵深或 `finger4/5` 微弱差异翻转，缺少对“三度+三度 / 三度+四度 / 四度+三度”转位开口结构的乐理先验。

### 1.3 `selectFixedOptimalChordTuple` 过早剪枝切断了保持音与横向上下文
- **现象还原**：
  - [`generateSliceCandidates`](../src/solver/costModel.ts#L150-L263) 对无锚点的 3+ 音柱式和弦在 `EMPTY_HELD_FINGERS` 下直接裁剪为 **唯一 1 个候选**（`candidates.length === 1`）。
- **代码根因**：
  - 当该拍同时存在跨切片活跃保持音（`slice.heldNotes.length > 0`）时，在 `EMPTY_HELD_FINGERS` 下选出的唯一静态候选可能直接与正在保持的手指冲突（触发 `heldStealPenalty = 400` 甚至指序倒置），而次优合法和弦指型已被提前丢弃。

### 1.4 12 调式音阶与长琶音中 `2↔1` 碎穿指压倒 `3+4` 标准周期穿指
- **现象还原**（12 大调单八度上行音阶实测）：
  - **F 大调右手（`F-G-A-Bb-C-D-E-F`）**：标准指法为 **`1-2-3-4-1-2-3-4`**（`4` 指落唯一黑键 `Bb`，随后 `4→1` 穿指到白键 `C`），当前求解器输出 **`1-2-1-2-1-2-3-4`**（连续两次白键 `2→1` 碎穿指）。
  - **Db 大调右手（`Db-Eb-F-Gb-Ab-Bb-C-Db`）**：标准指法为 **`2-3-1-2-3-4-1-2`**（`1` 指固定落两个白键 `F` 和 `C`），当前求解器在尾音输出 **`2-3-1-2-3-4-5-5`**（宁可在 `C→Db` 上用 `5→5` 同指滑键，也不愿在 `Bb(4)→C(1)` 穿指）。
  - **Eb / Ab / Bb 大调左手**：标准指法为 **`3-2-1-4-3-2-1-3`**（`{3指组} + {4指组}` 七音八度周期），当前求解器输出 **`3-2-1-3-2-1-3-2`**（连续两次 `1→3` 跨指，完全不用 `4` 指跨黑键）。
  - **Bb 大调右手（`Bb-C-D-Eb-F-G-A-Bb`）**：标准指法为 **`2-1-2-3-1-2-3-4`**（或 `4-1-2-3-1-2-3-4`，`1` 指落白键 `C` 和 `F`），当前求解器输出 **`2-3-1-2-1-2-3-4`**（`1` 指错落在 `D` 和 `F`）。
- **代码根因**：
  - [`weights.json`](../src/solver/weights.json#L52-L54) 中 `cross2Extra = 0.3` 远低于 `cross4Extra = 3.2`（叠加 `finger4 = 0.35` 后，一次 `4↔1` 的额外惩罚超过两次 `2↔1` 之和）。
  - [`evaluateDirectedNoteTransition`](../src/solver/costModel.ts#L561-L668) 未区分**“黑键跳板→白键拇指（Black-to-White Thumb Crossing）”**与**“纯白键级进穿指（White-to-White Stepwise Crossing）”**：
    - 在真实钢琴键盘上，黑键高出白键且位置靠里，当 `4` 指（或 `3`/`2` 指）按在黑键上时，手掌天然拱起，大拇指 `1` 从下方穿到相邻白键（如 RH `Bb(4)→C(1)`，或 LH 从白键 `1` 指跨上黑键 `4` 指如 `F(1)→Gb(4)`、`G(1)→Ab(4)`）极其顺畅，物理阻力远小于白键到白键的 `4↔1`；
    - 反之，在两个相邻白键级进（`1..2` 半音）之间做 `2↔1` 穿跨指（如 `G(2)→A(1)`）则会造成手部频繁缩拢抽动，在规范音阶演奏中应予抑制。

## 2. 总体优化架构（方案 1 + 方案 2）

保持现有 **100% 浏览器本地纯 TypeScript + 零后端 + Web Worker `<= 200 ms` 性能预算** 不变，在 [`src/solver/costModel.ts`](../src/solver/costModel.ts) 与 [`src/solver/weights.json`](../src/solver/weights.json) 中实施两项核心增强：

1. **方案 1（和弦指法优化）**：
   - **柱式和弦 `1–5` 外框黑键惩罚豁免**：在 3+ 音和弦中，当手部外侧音由 `1` 指和/或 `5` 指承担外框时，豁免 `avoidThumbOnBlack` 的高额黑键惩罚与 `pinkyBlack` 惩罚；
   - **和弦转位几何软先验（`computeChordVoicingPrior`）**：基于三音和弦与四音和弦的音程开口比例（原位 / 第一转位 / 第二转位 / 七和弦），对偏离教科书标准指型的内部手指分配施加软偏置（Soft Prior Bias）；
   - **保持音感知的柱式和弦候选保留**：无保持音时维持单候选极速收敛；存在活跃保持音（`slice.heldNotes.length > 0`）或前后紧接平行和弦时，保留垂直代价 **Top-3** 和弦候选进入 DP 搜索，兼顾标准手型与多声部避让。
2. **方案 2（12 调式音阶与琶音指法优化）**：
   - **黑白键地形感知的穿跨指模型（Terrain-Aware Thumb Crossing）**：
     - **黑键跳板减免（Black-Pivot Relief）**：对 `黑键(2/3/4) → 白键(1)` 穿指及 `白键(1) → 黑键(2/3/4)` 跨指大幅减免 `cross4Extra` 并给予顺畅过渡奖励，使 `1` 指天然锚定在黑键组后的首个白键（`C`、`F` 等）；
     - **纯白键级进 `2↔1` 碎穿指抑制**：当相邻两音均为白键且处于二度级进（`absD <= 1.2`）时，提高 `2↔1` 穿跨指代价，杜绝 `1-2-1-2` 碎片化换把；
     - **黑键调起手/收尾与长琶音穿指协同**：抑制级进音阶尾音 `5→5` / `1→1` 同指异音滑键；在三度/四度分解和弦（长琶音）跨八度穿跨指中同样启用黑键跳板优待，使 `Eb/Ab/Db` 等黑键调长琶音自然遵循“拇指落白键”原则。

## 3. 方案 1 详细设计：和弦指法优化

### 3.1 柱式和弦外框（Outer Frame）黑键惩罚豁免（[`src/solver/costModel.ts`](../src/solver/costModel.ts)）

在 `computeVerticalCost` 中，区分“单音/双音”与“3+ 音和弦外框”的黑键代价：

1. 对切片 `slice.notes`（已按 MIDI 升序排列，$k = \text{notes.length}$）：
   - 右手（`hand === "RH"`）：最低音索引 `thumbSideIdx = 0`，最高音索引 `pinkySideIdx = k - 1`；
   - 左手（`hand === "LH"`）：最高音索引 `thumbSideIdx = k - 1`，最低音索引 `pinkySideIdx = 0`。
2. 当 $k \ge 3$ 且外跨度 `outerSemitones = notes[k - 1].midi - notes[0].midi >= 5` 时：
   - 若 `i === thumbSideIdx && f === 1 && isBlackKey(n.midi)`：
     - 视为**和弦外框拇指支撑**，仅收取基础学习权重 `vw.thumbBlackLearned (0.24)`，不叠加 `vw.thumbBlackAvoid (4.5)`；
   - 若 `i === pinkySideIdx && f === 5 && isBlackKey(n.midi)`：
     - 视为**和弦外框小指支撑**，将 `vw.pinkyBlack (1.152)` 衰减至 `vw.pinkyBlack * 0.15`（约 `0.17`），保证 `5` 指在黑键外框上始终优于 `4` 指（`finger4 = 0.35` + 内指挤压代价）。
   - **边界保护**：对于 $k = 2$ 的双音（特别是八度双音 `semitoneDiff === 12`），保留原有的 `thumbBlackCost` 与 `pinkyBlack` 不变，确保半音阶连奏八度（`C4-C5 → Db4-Db5`）与浪漫派左手八度（`Bb2-Bb3 → B2-B3`）继续在黑键八度上自然切换 `1-4` / `5-1`。

### 3.2 和弦转位几何软先验 `computeChordVoicingPrior`（[`src/solver/costModel.ts`](../src/solver/costModel.ts)）

在 `computeVerticalCost` 中新增 `computeChordVoicingPrior(slice, fingers, weights)` 累加项：

#### A. 三音和弦转位先验（$k = 3$，`6 <= outerSemitones <= 9`）
设三音 MIDI 升序为 $m_0 < m_1 < m_2$，下方音程 $\Delta_{\text{low}} = m_1 - m_0$，上方音程 $\Delta_{\text{high}} = m_2 - m_1$：

1. **原位三和弦（$\Delta_{\text{low}} \in [3, 4]$ 且 $\Delta_{\text{high}} \in [3, 4]$，三度 + 三度）**：
   - 标准外框与中指对称分布：右手目标 **`[1, 3, 5]`**，左手目标 **`[5, 3, 1]`**。
   - 若外框未用 `1` 和 `5`（如 `2-4-5`、`1-2-4`），施加外框偏离代价 `+2.6`；
   - 若外框为 `1` 和 `5` 但中间指未用 `3`（如 `1-2-5`、`5-2-1`），施加内指偏离代价 `+1.8`。
2. **第一转位六和弦（$\Delta_{\text{low}} \in [3, 4]$ 且 $\Delta_{\text{high}} \in [5, 6]$，下三度 + 上四度）**：
   - **右手（RH）**：上方为四度大开口，标准指法为 **`[1, 2, 5]`**（将四度跨度交给 `2–5` 指）。对非 `[1, 2, 5]` 候选施加 `+1.8`（外框非 `1..5` 额外 `+1.5`）。
   - **左手（LH）**：上方为四度（对应左手 `3–1` 或 `2–1` 指）。标准指法为 **`[5, 3, 1]`**（当底音为黑键而上方两音为白键如 `F#-A-D`、`G#-B-E` 时，`[5, 3, 1]` 与 `[5, 2, 1]` 均免罚；其余地形偏好 `[5, 3, 1]`，偏离罚 `+1.6`）。
3. **第二转位四六和弦（$\Delta_{\text{low}} \in [5, 6]$ 且 $\Delta_{\text{high}} \in [3, 4]$，下四度 + 上三度）**：
   - **右手（RH）**：下方为四度，由 `1–3` 指承担，标准指法为 **`[1, 3, 5]`**（偏离罚 `+1.8`）。
   - **左手（LH）**：下方为四度，由 `5–2` 指承担，上方三度由 `2–1` 指承担，标准指法为 **`[5, 2, 1]`**（偏离罚 `+1.8`）。

#### B. 四音和弦转位与七和弦先验（$k = 4$，`9 <= outerSemitones <= 12`）
设四音相邻半音差为 $\Delta_0 = m_1 - m_0$、$\Delta_1 = m_2 - m_1$、$\Delta_2 = m_3 - m_2$：

1. **外框约束**：右手首尾偏离 `1..5` 或左手首尾偏离 `5..1` 时施加 `+2.8`。
2. **空缺手指对齐最大四度开口（$\max(\Delta_0, \Delta_1, \Delta_2) \ge 5$）**：
   - **顶部四度开口（$\Delta_2 \ge 5$ 且 $\Delta_2 > \Delta_1, \Delta_0$，如原位八度三和弦 `C-E-G-C`）**：
     - 右手跳过 `4` 指 $\rightarrow$ 偏好 **`[1, 2, 3, 5]`**（偏离罚 `+1.6`）；
     - 左手跳过 `4` 指或纯白键跳过 `3` 指 $\rightarrow$ 黑键调偏好 **`[5, 3, 2, 1]`**，纯白键允许 **`[5, 3, 2, 1]` / `[5, 4, 2, 1]`**。
   - **中部四度开口（$\Delta_1 \ge 5$ 且 $\Delta_1 > \Delta_0, \Delta_2$，如第一转位 `E-G-C-E`）**：
     - 双手均跳过 `3` 指（用 `2–4` 指跨中部四度）$\rightarrow$ 右手偏好 **`[1, 2, 4, 5]`**，左手偏好 **`[5, 4, 2, 1]`**（偏离罚 `+1.6`）。
   - **底部四度开口（$\Delta_0 \ge 5$ 且 $\Delta_0 > \Delta_1, \Delta_2$，如第二转位 `G-C-E-G`）**：
     - 左手跳过 `4` 指（用 `5–3` 跨底部四度）$\rightarrow$ 偏好 **`[5, 3, 2, 1]`**（偏离罚 `+1.6`）；
     - 右手偏好 **`[1, 2, 4, 5]`**（当第二音 $m_1$ 为黑键如 `Ab-Db-F-Ab` 时同时允许 **`[1, 3, 4, 5]`**）。

### 3.3 保持音感知的柱式和弦候选保留（[`src/solver/costModel.ts`](../src/solver/costModel.ts)）

升级 `selectFixedOptimalChordTuple` 为 `selectOptimalChordTuples(slice, allCandidates, profile)`：
- 当 `slice.heldNotes.length === 0`（无跨切片保持音）时：返回垂直代价最优的 **1 个** 标准和弦指法 `[bestTuple]`（保持单测 `candidates.length === 1` 与极速 DP 性能）；
- 当 `slice.heldNotes.length > 0`（存在跨切片保持音）时：按无保持音基础垂直代价排序后，返回 **Top-3** 候选指型（如 `[1,3,5], [1,2,5], [2,3,5]`），交由 A* / Beam Search 在结合实际保持音映射 `relOpt.heldFingers` 后动态选出不抢指的最优解。

## 4. 方案 2 详细设计：12 调式音阶与琶音指法优化

### 4.1 黑白键地形感知的穿指/跨指代价（[`src/solver/costModel.ts`](../src/solver/costModel.ts)）

在 `evaluateDirectedNoteTransition` 中，根据 `prevIsBlack = isBlackKey(prevMidi)` 与 `currIsBlack = isBlackKey(currMidi)` 细化 `isThumbUnder` 与 `isCrossOver` 的代价计算：

1. **黑键跳板穿指优待（`isThumbUnder`: `prevFinger ∈ {2,3,4} → currFinger = 1`）**：
   - 当 `prevIsBlack && !currIsBlack`（从黑键穿到白键，如 `Bb(4)→C(1)`、`Eb(3)→F(1)`、`F#(4)→G(1)`）：
     - 若 `prevFinger === 4`：将 `cross4Extra (3.2)` 减免为 **`0.45`**（消除 `4→1` 在黑键跳板上的虚高壁垒）；
     - 若 `prevFinger === 3`：给予黑键下穿顺畅减免 **`-0.35`**；
     - 若 `prevFinger === 2`：仅在跨度 `absD >= 1.0`（如黑键起点 `Bb(2)→C(1)` 或琶音跳进）时保持低代价 `cross2Extra (0.3)`。
2. **白键拇指跨黑键优待（`isCrossOver`: `prevFinger = 1 → currFinger ∈ {2,3,4}`）**：
   - 当 `!prevIsBlack && currIsBlack`（从白键 `1` 指跨向黑键，如左手上行 `F(1)→Gb(4)`、`G(1)→Ab(4)`、`C(1)→Db(3)`）：
     - 若 `currFinger === 4`：将 `cross4Extra (3.2)` 减免为 **`0.55`**；
     - 若 `currFinger === 3`：给予顺畅减免 **`-0.25`**。
3. **纯白键二度级进 `2↔1` 碎穿指抑制**：
   - 当 `!prevIsBlack && !currIsBlack && absD <= 1.25`（两个相邻白键之间的二度级进）且发生 `2 → 1` 穿指或 `1 → 2` 跨指时：
     - 额外施加 **`+2.4`** 的短步碎穿指惩罚（使白键音阶段必须走完 `1-2-3` 或 `1-2-3-4` 后再穿跨指，彻底消除 `F` 大调右手 `1-2-1-2-1-2-3-4` 的畸形路径）。
4. **白键到白键 `4↔1` 的适度校准**：
   - 在纯白键级进（`!prevIsBlack && !currIsBlack`）上的 `4↔1` 保留较高 `cross4Extra`（如 `2.0`），确保纯白键 `C/G/D/A/E` 大调音阶在第一八度内优先使用 `3→1`（`1-2-3-1-2-3-4-5`），而不会在 `C-D-E-F` 上误走 `1-2-3-4-1`。

### 4.2 音阶级进序列中的 `3+4` 周期律与首尾边界优化（[`src/solver/costModel.ts`](../src/solver/costModel.ts)）

在 `computeHorizontalCost` 的单音对单音（`isMonoPair`）过渡中补充两项轻量级乐理约束：

1. **抑制中速/快速级进中的同指滑键（`5→5` / `1→1`）**：
   - 当单音级进（`1 <= Math.abs(currMidi - prevMidi) <= 2`）且 `prevFinger === currFinger` 时，若 `dt <= 0.35s`，提高同指级进滑键代价（或确保 `sameFingerBase = 6.0` 高于合法的黑键 `4→1` 穿指代价），从而让 `Db` 大调右手结尾 `Bb4 → C5 → Db5` 自然选择 `4 → 1 → 2` 而非 `4 → 5 → 5`。
2. **黑键调左手 `{3指组} + {4指组}` 引导**：
   - 在左手单音上行（或右手下行）中，当 `1` 指落在白键 `F` 或 `C`（或 `G`、`D`）且下一音为黑键时，由于 `4` 指跨黑键的 `cross4Extra` 已获减免，且后续三黑键/双黑键组若只用 `3-2-1` 会导致下一轮 `1` 指被迫落黑键（触发 `thumbBlackAvoid = 4.5`），DP 的全局前瞻（`computeAnchorLookahead` 1st-order backward DP）将自动选出唯一不让 `1` 指落黑键的 **`3+4` 标准七音周期**（如 `Eb/Ab/Bb` 大调左手 `3-2-1-4-3-2-1-3`）。
